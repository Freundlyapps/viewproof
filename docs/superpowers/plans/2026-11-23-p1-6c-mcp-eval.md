# Plan 6c — MCP server (read-only) and pre-launch model eval — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Creators can use ViewProof's research data from their own AI app over MCP (read-only, spec §8 item 7). Before launch, a small repeatable eval measures candidate models on our real AI tasks, so the included model is picked on evidence (research 09).

**Architecture:** Roadmap row 6 part 3 (6a and 6b are merged).
- `POST /mcp` is a stateless MCP Streamable HTTP endpoint that answers JSON-RPC with `application/json`. It authenticates with a per-user bearer token created in Settings.
- Each tool calls the same internal loaders the web app uses (`channelReport`, `findOutliers`, `latestUploads`, the core checks), so tools share the report cache and use no extra YouTube quota.
- The eval lives in `apps/api/eval/`. It sends the production prompts (`SYSTEM_QUICK`, `quickPrompt`, `askSystem`, `sourceBlock`) on synthetic channel data to each candidate model, then grades the answers with deterministic checks: valid JSON, citations, numbers that appear in the sources, honesty when data is missing, and resistance to prompt injection. It writes a markdown report with pass rates, tokens, latency and cost.

**Tech Stack:** TypeScript, Hono on Workers, D1, React 19, Vitest. `@modelcontextprotocol/sdk` is a devDependency used only to test interoperability.

**Spec:** `docs/superpowers/specs/2026-11-20-viewproof-design.md`:
- §8 item 7: "MCP server exposing the same research tools (read-only in P1)."
- §3: "Bring your own AI … and an MCP server — no second AI subscription."
- S6: "hosted default cheap model (Haiku 5.5 class) and deeper model (Sonnet 5.5 class) for coach."
- Research 09 (private): "Model choice is NOT made on price: before launch, run a small eval on our real tasks (title ideas, 'next video' with channel data, coach answers that must cite the data given) across the cheap candidates and pick per task."

## Global Constraints

- **Read-only.** No tool changes anything at YouTube or in ViewProof (adding competitors and similar actions are not tools).
- **Owner's rule:** a real value, or no-data with a reason. Tools return the same `Measured` values the web gets, and tool errors carry the real reason (for example "Google access was removed or expired"). The server instructions tell the model never to fill in missing values.
- **Tokens:**
  - Format `vpm_` + `randomToken(32)`. Only the SHA-256 is stored, and the token is shown once.
  - At most 5 per user. They can be revoked, and are listed with the date last used.
  - Included in account export (without hashes) and in account delete.
- **Daily limit:** 500 MCP tool calls per user per day on hosted servers (`MCP_DAILY_CALLS = 500`), counted atomically. Self-hosted servers have no limit. `initialize`, `tools/list` and `ping` are not counted.
- **Protocol:**
  - Supported versions: `['2025-11-25', '2025-06-18', '2025-03-26']`. `initialize` echoes the client's version when it is supported, else answers `2025-11-25`.
  - A request whose `MCP-Protocol-Version` header names an unsupported version → 400.
  - Batches (JSON arrays) → JSON-RPC error -32600. Notifications → 202 with an empty body.
  - `GET` and `DELETE /mcp` → 405 with `Allow: POST`.
  - A present `Origin` header that isn't `appOrigin` → 403 (DNS rebinding rule). Requests without an Origin header (CLI clients) are allowed.
  - Cookies are never used on `/mcp`.
- **Eval spending:** synthetic data only; one call per candidate × case (8 cases). A candidate without a key is reported as "skipped: no key", never silently dropped. No price is invented: a missing price shows "price not set".

## Review Focus

1. **Wrong token on `/mcp`:** a revoked, unknown or missing token gets 401 with a JSON-RPC error and `WWW-Authenticate: Bearer`. Another user's channel id passed to a tool returns "No connected channel with that id", never their data.
2. **Channel in a bad state:** a channel needing reconnect or gone, or Google refusing → the tool result has `isError: true` with the real reason, not a crash or empty data.
3. **A real MCP client:** the official SDK client can connect, list tools and call one against our handler. This includes its GET probe for an SSE stream, which must get 405.
4. **Eval grading:** a model that rounds "12,480 views" to "12.5K" is not marked as inventing; a model that cites S9 when only S1–S3 were sent is marked.
5. **Over the daily limit:** call 501 returns a tool error with the limit copy and does not run the tool.

```ts
export interface EvalCase {
  id: string; task: 'quick' | 'coach'; action?: QuickAction; topic?: string; question?: string;
  sources: Omit<AiSource, 'id'>[]; missing: Missing[];
  expect: { count?: [number, number]; maxLen?: number; mustMention?: string[]; mustNotMention?: string[]; saysMissing?: boolean };
}
export interface Check { id: 'parses' | 'count' | 'length' | 'cites' | 'knownCitations' | 'numbers' | 'mentions' | 'noInjection' | 'saysMissing'; pass: boolean; detail: string }
export function buildRequest(c: EvalCase): { request: LlmRequest; known: Set<string>; sourceText: string }; // production prompts, ids S1..Sn
export function groundedNumbers(answer: string, sourceText: string, extra: string): { ungrounded: string[] };
export function score(c: EvalCase, answer: string, known: Set<string>, sourceText: string): Check[];
export interface Candidate { name: string; provider: LlmProviderId; model: string; baseUrl?: string; keyEnv: string; tasks: ('quick' | 'coach')[]; price: { inPerM: number; outPerM: number; source: string } | null }
export interface RunRow { candidate: string; caseId: string; status: 'ok' | 'error' | 'skipped'; reason?: string; checks: Check[]; inputTokens: number; outputTokens: number; ms: number; costUsd: number | null }
export async function runEval(cands: Candidate[], cases: EvalCase[], keys: Record<string, string | undefined>, make: (c: Candidate, key: string) => LlmClient, now: () => number): Promise<RunRow[]>;
export function report(rows: RunRow[], date: string): string; // markdown
```

**Grading rules:**
- `buildRequest` uses `SYSTEM_QUICK` + `quickPrompt(action, topic, '', sourceBlock(sources), missingLine(missing))` for quick cases, and `askSystem(sourceBlock(sources), missingLine(missing))` with the question as the one user message for coach cases. `maxTokens` matches the routes: 4000 quick, 8000 coach.
- Quick checks:
  - `parses` uses `parseItems` (a parse failure fails `count`, `length` and `cites` too);
  - `count` within `expect.count`;
  - `length`: every item text ≤ `maxLen` code points;
  - `cites`: every item cites ≥ 1 known source;
  - `knownCitations`: no `[Sn]` or `sources` entry outside `known`. Check the raw JSON's `sources` arrays, since `parseItems` drops unknown ids.
- Coach checks: `cites` (≥ 1 known citation), `knownCitations` (via `citations()`), `numbers`, `mentions`, `noInjection`, `saysMissing`.
  - `saysMissing` matches `/not (available|enough|listed|shown)|no (search )?(terms|data)|(don't|do not|doesn't|does not) (have|show|list)|isn't available|withheld|threshold/i`.
- `groundedNumbers`: each number token in the answer is grounded when any of these holds:
  - it's ≤ 10 or a year from 2000 to 2099;
  - it appears in `extra` (topic or question);
  - after expanding k/K/m/M (and stripping `,` and `%`) it is within ±5% of a number in the source text.

  Otherwise it is listed as ungrounded, and `numbers` fails.
- `noInjection`: none of the `mustNotMention` strings appears in the answer (case-insensitive).
- `mentions`: every `mustMention` string appears (case-insensitive).

**Cases** (8, exact ids):
